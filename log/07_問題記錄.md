# 07 — 問題記錄（踩過的坑）

> 這份文件記錄開發過程中遇到的所有問題、原因、和解法。  
> 目的：下次遇到類似問題時可以快速找到答案，也方便 code review 時說明為什麼這樣寫。

---

## 問題 1：Supabase 查詢回傳空陣列，但資料庫有資料

**症狀：**  
程式沒有報錯，但 `data` 是空陣列 `[]`，確定資料庫裡有資料。

**原因：**  
Supabase 預設開啟 **Row Level Security（RLS）**。開啟時，所有查詢都被擋掉、靜默回傳空陣列，不會報錯。

**解法：**  
在 Supabase SQL Editor 執行：
```sql
alter table public.leetcode_records disable row level security;
```

**學到什麼：**  
Supabase 的 RLS 很隱晦——它不會拋出錯誤，只是讓你拿不到資料。個人專案不需要複雜權限控管時，直接關掉。

## 問題 2：Next.js 15 的 `params` 不能直接解構

**症狀：**  
在題目詳情頁 `src/app/problems/[id]/page.tsx` 直接寫 `const { id } = params` 會有 TypeScript 警告或執行期錯誤。

**原因：**  
Next.js 15 把動態路由的 `params` 改成了 **Promise**（不同於舊版本直接是物件）。

**解法：**  
```typescript
// ❌ 舊版（Next.js 14 以前）
export default function Page({ params }) {
  const { id } = params;
}

// ✅ Next.js 15
export default async function Page({ params }) {
  const { id } = await params;  // 必須 await
}
```

**學到什麼：**  
Next.js 版本之間有破壞性更新，不能照舊文件寫。遇到怪問題時先查目前使用的版本。

## 問題 3：在 Client Component 裡引入 server.ts 造成金鑰外洩

**症狀：**  
TypeScript 沒報錯，但瀏覽器控制台出現警告，或者 Supabase 的 service key 出現在前端 bundle 裡。

**原因：**  
`src/lib/supabase/server.ts` 使用的是需要在伺服器執行的 API。如果在 `'use client'` 元件裡 `import from 'server.ts'`，Next.js 會把整個 server 程式碼打包進前端，導致密鑰外洩。

**解法：**  
嚴格區分兩個檔案：
- `server.ts` → 只在 Server Component 或 API Route 裡引入
- `client.ts` → 只在 `'use client'` 元件裡引入

**記憶法：** 檔名和元件類型要一致，「server 用 server，client 用 client」。

## 問題 4：Chrome Extension Content Script 跨域請求被擋

**症狀：**  
Content Script 直接向 `localhost:3000/api/webhook` 發送 POST，瀏覽器顯示 CORS 錯誤。

**原因：**  
Content Script 被注入到 `leetcode.com` 頁面，屬於 `leetcode.com` 的安全環境。從 `leetcode.com` 發請求到 `localhost:3000` 是跨域請求，瀏覽器的同源政策（Same-Origin Policy）會擋掉。

**解法：**  
讓 Background Service Worker 代替發送請求：
1. Content Script 用 `chrome.runtime.sendMessage()` 傳資料給 Background
2. Background 不屬於任何網頁，不受同源政策限制
3. Background 發送 HTTP 請求給 Webhook

**架構示意：**
```
content.ts（leetcode.com 頁面）
  ↓ chrome.runtime.sendMessage()
background.ts（獨立於任何網頁）
  ↓ fetch()
localhost:3000/api/webhook（或 Vercel 網址）
```

## 問題 5：Extension 改了程式碼但沒有生效

**症狀：**  
修改了 TypeScript 檔案，重新整理 LeetCode，但行為沒有改變。

**原因：**  
Extension 跑的是 `extension/dist/` 裡編譯後的 JavaScript，而不是原始 TypeScript 原始碼。改了 `.ts` 但沒有重新 build，所以跑的還是舊版。

**解法（每次改完 Extension 都要做這三步）：**
```bash
# 1. 重新編譯
node extension/build.js

# 2. 在 chrome://extensions/ 點 Extension 的「重新整理」按鈕

# 3. 重新整理 LeetCode 頁面
```

**學到什麼：**  
TypeScript 不能直接在瀏覽器跑，必須先編譯。忘記 build 是最常見的除錯誤區。

## 問題 6：AI 視覺化功能 — Google Gemini API 完全失效

**症狀：**  
嘗試使用 Google Gemini API 替代 Anthropic，所有嘗試都失敗。

**嘗試過的 API 和失敗原因：**

| 嘗試 | 錯誤訊息 | 原因 |
|---|---|---|
| `@google/genai` SDK, `gemini-2.0-flash` | `limit: 0` quota exceeded | 帳戶有 billing，免費額度變 0 |
| `@google/generative-ai` SDK, `gemini-1.5-flash` | 404 not found in v1beta | 此帳戶的 v1beta 沒有這個模型 |
| REST API v1 + system_instruction | `system_instruction unknown field` | v1 REST API 不支援 system_instruction |
| `gemini-2.0-flash-lite` | `limit: 0` quota exceeded | 同上 |
| 新申請的 AI Studio API Key | `API key not valid` | 金鑰複製時可能錯誤（結尾 `I` vs `l`） |

**根本原因：**  
Google Cloud Project 開啟了 billing，導致免費 API tier 的配額變成 0，所有免費模型都無法使用。

**最終解法：**  
暫時停用視覺化功能（`code-visualizer.tsx` 的引用被 comment out）。  
等有 Anthropic API Key 後再重新啟用（程式碼已保留，只需取消 comment）。

**如何重新啟用視覺化功能：**
1. 申請 Anthropic API Key：https://console.anthropic.com
2. 在 `.env.local` 填入 `ANTHROPIC_API_KEY=sk-ant-...`
3. 在 Vercel 環境變數也填入
4. 在 `src/components/detail/solution-tabs.tsx` 取消 CodeVisualizer 的 comment

## 問題 7：Vercel 部署後 Dashboard 顯示空白（題庫沒資料）

**症狀：**  
本機可以看到 96 道題目，但 `https://vibe-leetcode.vercel.app` 顯示空白或 0 題。

**原因：**  
Vercel 的環境沒有 `.env.local` 這個檔案（`.gitignore` 裡有把它排除）。  
Supabase 的連接資訊（URL、金鑰）沒有被傳到 Vercel，所以程式連不到資料庫。

**解法：**  
在 Vercel 專案的 **「Environment Variables」** 頁面（左側選單）手動填入：
- `NEXT_PUBLIC_SUPABASE_URL`
- `NEXT_PUBLIC_SUPABASE_ANON_KEY`  
- `WEBHOOK_SECRET`
- `NEXT_PUBLIC_USE_MOCK` = `false`

填完後必須 **Redeploy**（在 Deployments 頁面右鍵 → Redeploy）才會生效。

**學到什麼：**  
`.env.local` 是本機專用的，雲端環境要另外設定環境變數。「我本機可以跑但雲端不行」的問題有 90% 是這個原因。

## 問題 8：`solutions` 欄位讀出來是 `null`

**症狀：**  
某些題目的解法 tab 顯示空白，或者程式出現 `Cannot read properties of null (reading 'map')` 錯誤。

**原因：**  
資料庫裡的 `solutions` 欄位預設值雖然設成 `'[]'::jsonb`，但如果是透過其他方式建立的資料（例如舊版 Extension），可能存入了 `null`。

**解法：**  
讀取時加上保護：
```typescript
const solutions = record.solutions ?? [];
// 而不是直接用 record.solutions.map(...)
```

**學到什麼：**  
任何從外部來的資料（API、資料庫）都要假設可能是 `null` 或 `undefined`，加上預設值保護。

## 問題 9：刪除解法後，Tab 顯示錯誤

**症狀：**  
刪除最後一個解法（或不是第一個解法），Tab 切換到不存在的 index，顯示空白。

**原因：**  
原本的 `<Tabs defaultValue="0">` 是「非受控元件」（uncontrolled），刪除後 active tab 不會自動調整。

**解法：**  
改成「受控元件」（controlled），自己管理 active tab 的狀態：
```typescript
const [activeTab, setActiveTab] = useState('0');

// 刪除時調整 activeTab
const deleteSolution = async (i: number) => {
  const newSolutions = solutions.filter((_, idx) => idx !== i);
  // 如果刪的是當前 tab 或後面的 tab，調整到前一個
  if (parseInt(activeTab) >= newSolutions.length) {
    setActiveTab(String(Math.max(0, newSolutions.length - 1)));
  }
  // 更新 Supabase...
};

return <Tabs value={activeTab} onValueChange={setActiveTab}>
```

**學到什麼：**  
React 的 uncontrolled vs controlled 元件選擇很重要。需要程式動態控制值時，要用 controlled（有 `value` + `onChange` prop）。

## 問題 10：`rehype-highlight` 程式碼無顏色

**症狀：**  
Markdown 筆記裡的程式碼區塊沒有語法高亮顏色，都是純白文字。

**原因：**  
`rehype-highlight` 只負責加上 CSS class（例如 `hljs-keyword`），顏色還需要引入 CSS 主題檔案。

**解法：**  
在 `solution-tabs.tsx` 頂部引入主題：
```typescript
import 'highlight.js/styles/github-dark.css';
```

## 問題 11：題目描述沒有辦法從舊資料補上

**情況：**  
新增了 `description` 欄位後，已存在的 96 道題目都沒有 `description`。  
重新用 Extension 提交是個選擇，但要一題一題手動操作太麻煩。

**解法：**  
建立 `/api/fetch-description` 端點：
- 接收 `{ slug, recordId }`（slug 是 LeetCode 的題目 URL 名稱，例如 `two-sum`）
- 伺服器端呼叫 LeetCode 的 GraphQL API，抓取 `content`（HTML 格式的題目描述）
- 存回 Supabase 對應的題目
- 前端在題目詳情頁加一個「載入描述」按鈕，點一下就自動填入

為什麼要在伺服器端發請求？  
從瀏覽器直接呼叫 `leetcode.com/graphql` 會被跨域限制擋掉。  
但從 Next.js API Route（伺服器端）呼叫就沒有這個問題。

## 問題 12：Windows PowerShell 的 curl SSL 錯誤

**症狀：**  
執行 `curl` 測試 API 時出現 `CRYPT_E_NO_REVOCATION_CHECK` 錯誤。

**原因：**  
Windows PowerShell 的 `curl` 別名（實際上是 `Invoke-WebRequest`）有時會在企業網路環境或某些設定下遇到 SSL 憑證驗證問題。

**解法：**  
改用真正的 curl 程式，或者直接用 Postman / Thunder Client（VS Code 插件）測試 API，不用在命令行測試。

## 問題 13：JSON 解析失敗 — AI 回傳帶有 Markdown 圍欄

**症狀：**  
`JSON.parse()` 拋出錯誤，顯示 `Unexpected token \`\` in JSON at position 0`。

**原因：**  
要求 AI（Claude）只回傳 JSON，但 AI 有時仍然會在 JSON 外面加上：
````
```json
{ ... }
```
````

這些 Markdown 程式碼圍欄（code fence）讓 `JSON.parse` 失敗。

**解法：**  
在 `JSON.parse` 之前先清理：
```typescript
const raw = response.content[0].type === 'text' ? response.content[0].text : '';
const clean = raw.replace(/```json\n?|```/g, '').trim();
const vizData: VizResponse = JSON.parse(clean);
```

**學到什麼：**  
AI 的輸出永遠不能 100% 信任格式正確，要做防呆處理。

## 問題 14：Dashboard 本週目標顯示 97/14

**症狀：**  
Dashboard 的 Activity 區塊原本應該顯示本週做了幾題，但畫面出現 `97/14`。  
這代表系統把所有歷史題目都算成本週新增。

**原因：**  
批量匯入 LeetCode 歷史 AC 題目時，會新增很多 record。這些 record 的 `created_at` 都是匯入當天，但 `solutions[0].code` 是空字串。  
如果熱力圖直接用 `record.created_at` 和 `records.length` 計算，就會把「匯入資料」誤認成「今天真的寫題」。

**解法：**
1. Activity 只統計有實際 code 的 solution：
   ```typescript
   solution.code.trim().length > 0
   ```
2. Webhook 新增解法時寫入：
   ```typescript
   submitted_at: new Date().toISOString()
   ```
3. 熱力圖、本週、本月優先用 `solution.submitted_at`，舊資料才 fallback 到 `record.created_at`。

**學到什麼：**  
資料庫 record 的建立時間不等於刷題時間。  
「匯入資料」和「實際提交」要分開看，否則 Dashboard 指標會很漂亮但不真實。

## 問題 15：Vercel Webhook 500，提示找不到欄位

**症狀：**  
LeetCode Console 顯示：

```txt
Webhook failed (500): Could not find the 'lc_slug' column of 'leetcode_records'
```

**原因：**  
本機程式碼和 Supabase 雲端資料表 schema 沒有完全同步。  
程式嘗試寫入 `lc_slug` 或 `description` 這類後來新增的欄位，但雲端資料表可能還沒加欄位。

**解法：**
- Webhook 寫入時只寫必要欄位，避免因可選欄位缺失導致整個同步失敗。
- 文件與 `supabase/schema.sql` 補上目前完整欄位。
- 若既有資料表缺欄位，在 Supabase SQL Editor 執行：

```sql
ALTER TABLE public.leetcode_records ADD COLUMN IF NOT EXISTS lc_slug text;
ALTER TABLE public.leetcode_records ADD COLUMN IF NOT EXISTS description text;
```

**學到什麼：**  
雲端能不能用，不只看程式碼，也要看資料表 schema 是否跟程式碼同步。
