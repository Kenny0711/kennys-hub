## 程式語言

### TypeScript
- 就是「加了型別檢查的 JavaScript」
- JavaScript 是網頁的程式語言，但容易打錯字、傳錯資料
- TypeScript 在你打錯的時候馬上畫紅線提醒你
- 所有 `.ts` 和 `.tsx` 檔案都是 TypeScript

**例子：**
```typescript
// 一般 JavaScript（不知道 name 是什麼型別）
function greet(name) { ... }

// TypeScript（明確說 name 必須是文字）
function greet(name: string) { ... }
```

## 前端框架

### Next.js
- 用來建立網站的框架，基於 React
- 同時處理「前端（你看到的畫面）」和「後端（API）」
- 這個專案用的是 Next.js App Router（比較新的寫法）

**重要概念：**
- `src/app/page.tsx` → 首頁
- `src/app/problems/page.tsx` → 題庫頁
- `src/app/api/webhook/route.ts` → API（不是畫面，是接資料的程式）

### React
- Next.js 底層用的 UI 函式庫
- 網頁上的每個元件（按鈕、卡片、表格）都是一個 React Component
- 用 `useState` 儲存畫面的狀態（例如「按鈕是否被點擊」）

**例子：**
```tsx
// 一個簡單的 React Component
function MyButton() {
  const [clicked, setClicked] = useState(false);
  return (
    <button onClick={() => setClicked(true)}>
      {clicked ? '已點擊' : '點我'}
    </button>
  );
}
```

## 資料庫

### Supabase
- 一個雲端資料庫服務，底層是 PostgreSQL（一種 SQL 資料庫）
- 提供好用的 JavaScript 函式庫，讓你用 JS 讀寫資料
- 也有 API，可以從任何地方存取

**這個專案的資料表：**
```
leetcode_records 表
├── id          唯一識別碼（UUID）
├── problem_id  LeetCode 題號（例如 1）
├── title       題目名稱（例如 Two Sum）
├── difficulty  難度（Easy / Medium / Hard）
├── tags        標籤陣列（例如 ["Array", "Hash Table"]）
├── proficiency 熟練度（生疏 / 理解 / 熟練）
├── solutions   解法陣列（JSON 格式，可有多筆）
├── description 題目描述（HTML 格式）
├── created_at  建立時間
└── updated_at  最後更新時間
```

**讀取資料的寫法：**
```typescript
const { data } = await supabase
  .from('leetcode_records')  // 選哪張表
  .select('*')               // 選哪些欄位（* = 全部）
  .eq('problem_id', 1)       // 篩選條件（problem_id = 1）
  .maybeSingle();            // 只拿一筆
```

## UI 元件庫

### shadcn/ui
- 預先做好的漂亮 UI 元件（按鈕、卡片、表格、下拉選單）
- 不需要自己從頭刻樣式
- 這個專案用到的元件：Button、Card、Badge、Table、Tabs、Select

### Tailwind CSS
- 不用寫 CSS 檔案，直接在 HTML 標籤上寫樣式
- 例如 `className="text-sm text-red-500 font-bold"` 等於設定字體大小、顏色、粗體

**例子：**
```tsx
// 傳統 CSS 寫法
<p className="myTitle">Hello</p>
// .myTitle { font-size: 14px; color: red; font-weight: bold; }

// Tailwind 寫法（直接在標籤上寫）
<p className="text-sm text-red-500 font-bold">Hello</p>
```

## Chrome Extension 相關

### Chrome Extension（MV3）
- 安裝在 Chrome 瀏覽器的小程式
- MV3 是目前最新版的擴充功能格式
- 由幾個檔案組成：

| 檔案 | 角色 | 說明 |
|---|---|---|
| `manifest.json` | 設定檔 | 宣告這個 Extension 要哪些權限 |
| `popup.html/ts` | 彈出視窗 | 點擊 Extension 圖示時看到的畫面 |
| `content.ts` | 內容腳本 | 跑在 LeetCode 頁面上，可以讀取頁面內容 |
| `background.ts` | 背景程式 | 在背景持續運行，負責送 HTTP 請求 |
| `main_world.ts` | 頁面腳本 | 跑在 LeetCode 的 JavaScript 環境裡，攔截 Submit 動作 |

### esbuild
- 把 TypeScript 編譯成瀏覽器看得懂的 JavaScript 的工具
- 比一般工具快很多
- `node extension/build.js` 就會呼叫 esbuild

## 後端 / API

### HTTP 請求（POST / GET）
- 瀏覽器和伺服器溝通的方式
- `GET`：「給我資料」（像是打開網頁）
- `POST`：「我要傳資料給你」（像是送出表單）
- Extension 用 POST 把解題資料送到 API

### Webhook
- 一種「主動推送資料」的方式
- 不是「我去問你有沒有新資料」，而是「有新資料時你主動告訴我」
- 這個專案裡，Extension 就是在 Accepted 後「主動 POST」到 API

### REST API
- 一種設計 API 的風格，用 URL + HTTP 方法來定義操作
- 例如：`POST /api/webhook` 表示「送資料到 webhook 這個端點」

## 開發工具

### Git / GitHub
- Git：追蹤程式碼修改歷史的工具（可以回到過去任何版本）
- GitHub：把程式碼放到雲端的平台
- 常用指令：
  ```bash
  git add .          # 選取要記錄的檔案
  git commit -m "說明"  # 建立一個存檔點
  git push           # 把存檔點推到 GitHub
  ```

### Vercel
- 把 Next.js 網站部署到雲端的服務
- 連接 GitHub 後，每次 `git push` 就自動重新部署
- 免費方案已夠個人使用

### npm
- Node.js 的套件管理器，像是「軟體商店」
- `npm install` = 安裝所有需要的套件
- `npm run dev` = 啟動開發伺服器
